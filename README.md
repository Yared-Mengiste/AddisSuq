# AddisSuq — Your neighbourhood, online

A working prototype of **AddisSuq**, a hyper-local retail marketplace for small and medium shops in
Addis Ababa. Built for the SE341 (Software Project Management) course demo, covering the four MVP
modules end to end:

| Module | Scope | Where to see it |
| --- | --- | --- |
| **A — Vendor onboarding & catalogue** | Shop registration → admin approval, product/inventory management | `/vendor/onboarding` → `/admin/vendors` → `/vendor/products` |
| **B — Customer accounts, location & discovery** | Sign-up with fake OTP, saved addresses, distance-ranked search | `/signup`, `/account`, `/search` |
| **C — Cart, checkout & payment** | Cart grouped by shop (one order per shop), simulated Telebirr / CBE Birr / Chapa / cash on delivery | `/cart` → `/checkout` |
| **D — Delivery/pickup, tracking & notifications** | Scheduling, visual status timeline, simulated SMS/e-mail feed | `/orders/[id]`, `/vendor/orders/[id]` |

## Run it

```bash
npm install
node scripts/seed.mjs   # (re)generate the JSON database in /data
npm run dev             # http://localhost:3000
```

Production build: `npm run build && npm start`.

## How to demo

There is **no real login**. The header has a **role switcher** (Customer / Vendor / Admin) and, inside
each role, a **demo-user picker**:

- **Customer** — pick any of the 15 seeded customers (or create one at `/signup`; the OTP screen always
  accepts **1234**). Browse → search → add to cart → checkout → track the order timeline.
- **Vendor** — pick a shop. `shop_05` (Mimi Mini-Market) starts **pending**, so the dashboard shows the
  waiting-for-approval state; approve it as the Admin to unlock it. `shop_01`–`shop_04` are approved and
  have orders to manage (advance statuses on `/vendor/orders/[id]` — each move sends the customer a
  simulated SMS into their notification feed).
- **Admin** — `/admin/vendors` reviews the pending application; `/admin/overview` shows live counts and
  GMV computed from the JSON files.

Business rules kept visible in the UI: 10-second order confirmation target, delivery fee by distance
band (free over 2,000 ETB, same-day within 7 km), one order per shop at checkout, stock decrementing on
order placement, auto-hide at 0 stock, and the fake 4-digit OTP.

## Architecture

- **Next.js (App Router) + TypeScript + Tailwind CSS v4**, React contexts for cart/auth/language state.
- **JSON file “database”** in `/data/*.json` — read/written only from Route Handlers (`app/api/**/route.ts`)
  via `fs/promises` with per-table write locks (`lib/db.ts`), pretty-printed so changes persist across
  refreshes during the demo.
- **`/lib`** — JSON helpers, distance calc + formatters (`geo.ts`), the order status machine and all
  business rules (`rules.ts`), notification writer (`notifications.ts`).
- **`/types`** — shared TypeScript types mirroring the JSON files 1:1.
- **`/scripts/seed.mjs`** — deterministic seeder: 6 categories, 5 shops (1 pending), 104 products,
  15 customers, 25 orders covering every status and payment method, 127 notifications.
- **Offline-safe artwork** — every product/shop image is a deterministic SVG generated by
  `/api/art/...` from its id, so the demo renders identically without internet.
- Payments and SMS/e-mail are **simulated** (fake gateway delay; notifications are written to
  `notifications.json` and shown as an in-app feed).
